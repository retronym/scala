# Wave four campaign: common brief

Read `SPIKE-BRIEF.md` beside this file first: builds, rules, the finding format and the deliverables apply. Read the section "What the spikes say about the method" of `README.md` and the report and harness of the spike track nearest yours (`reports/`, `harness/`). This file says what differs for the campaign.

- **Budget and rounds.** About 90 minutes and three steering rounds. A round is: run the generator for a fixed time, bucket and shrink failures, pre-triage, measure coverage, make one change to the generator or add one oracle. After each round append one object to `wave4/rounds/<track>.json` (a JSON array): `round`, `change` (what you changed before this round, one sentence), `cases`, `seconds`, `signatures_new`, `signatures_known`, `false_alarms` (count and cause), `coverage` (an object of scope name to lines covered and total), `largest_unreached` (five method or file names), `next` (what you will change and why). The coordinator shows these on a dashboard while you work, so write the file after every round, not at the end.
- **Coverage is required.** Attach JaCoCo to the JVM that runs the code under test: agent `~/Library/Caches/Coursier/v1/https/repo1.maven.org/maven2/org/jacoco/org.jacoco.agent/0.8.13/org.jacoco.agent-0.8.13-runtime.jar` with `destfile=<file>,includes=scala.*`; report with `org.jacoco.cli/0.8.13/org.jacoco.cli-0.8.13-nodeps.jar` beside it, `--classfiles` the jar of the build you ran (`lib/scala-library.jar` or `lib/scala-compiler.jar` and `lib/scala-reflect.jar`), `--xml`. Keep one XML per round in your scratch directory and render them at the end with `wave4/tools/coverage_treemap.py --prefix <your scope> --out wave4/reports/<track>-treemap.html "round 1=<xml>" ...`. Choose each round's change from the largest unreached code in your scope, not from earlier findings.
- **Do not aim at the earlier seams.** Generators produce ordinary usage. Self-aliasing of mutable collections, arithmetic at the Int extremes in ranges, and `@specialized` have been mined; give them ordinary weight or none. Yield in the spikes came from constructs a generator reached for the first time, never from more cases of the same kind: when a round is clean, add a construct or an oracle.
- **Known signatures.** `wave4/known-signatures.md` lists defects that are known and not fixed on the build you hunt on, with how to recognise them. Exclude them narrowly in your harness so they stop masking what is behind them, count what each exclusion discards, and add a line to that file when you meet another known one.
- **Build under test.** `/Users/jzaugg-virtus/code/.worktrees/scala/w3-int/build/pack` until `/Users/jzaugg-virtus/code/.worktrees/scala/w4-int/build/pack/lib/scala-compiler.jar` exists (the same plus the wave-four fixes); check at the start of each round and switch when it appears. Re-run each finding on the base and 2.13.18 as before.
- **Findings.** Prefixes: WJ (Java sources), WP (programs), WX (expressions and statements), WL (library), WS (seeded rewrites). Add to `finding.json` a string field `area_code` naming the part of the compiler or library the defect is in, one of: M collections, K library, J Java sources, JI Java interop, C typechecker, T types, Y typer / bridge, F front end, B backend, O optimizer, SPZ specialization, VCL value classes / SAM lambdas, ER erasure / universal members, EV evaluation order / purity, OVR overriding / mixin, L lambdalift, AS async, R reflect / pickler, X feature interaction. Before recording, search the wave-four findings too (`wave4/findings/*/finding.json`) and the open fork pull requests (`gh pr list --repo retronym/scala --state open --limit 600 --search '<keyword>'`, read-only).
- **Stop rule.** Two rounds in a row with no new signature and no coverage gain: stop, and say so in the report.
- **Report.** `wave4/reports/<track>-campaign.md`, and the harness changes in `wave4/harness/<track>/` (edit the spike's harness in place if you are continuing it; it is yours now).

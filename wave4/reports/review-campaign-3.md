# Review campaign-3: WS1, WS2

Verdicts: 1 real (WS1), 1 real and known in part (WS2). Severity: WS1 medium, WS2 low. No doubtful, by design, wrong or duplicate.

WS1 (medium, regression from 2.12): a lambda whose result is an inferred existential with a dependent quantifier bound (from returning a local class below a local abstract class and trait) is rejected when UnCurry expands it into an anonymous class. Reproduced on w4-int, w3-int, w3-base, 2.13.18, and 2.12.4 to 2.13.10; 2.11.12 compiles it. The expansion's parent comes from the body's skolem type (since 2.12.0's SAM refactoring, 7025be9a46) instead of the function type, and the skolem does not conform to the packed existential (the solver sets A to Nothing). The hunter understated the reach: the default strategy hits the same error for a lambda in a super-constructor argument or early definition, and mdoc and Scastie set -Ydelambdafy:inline for every Scala 2 compile (scala/bug#9824 and scala/bug#10782 workarounds). Scala 3.7.4 accepts the program. Fix: take the AbstractFunctionN type arguments from fun.tpe, as 2.11 did. No scala/bug ticket found.

WS2 (low, -Ycheck only): this is slow progress, not a hang. The type is scala/bug#10908's enormous lub (834 KB printed). The cost comes from the tree checker. checkSymbolRefsRespectScope wrongly reports every type parameter bound inside that refinement as out of scope: 1672 for T.f, 3082 for t498's lifted lambda. Each report renders the full signature before truncating it to 80 characters, which takes about 0.2 to 0.6 s per report, so 5 to 20 minutes in all. Thread dumps 4 s apart show steady progress through the warnings. The false reports also appear on small lubs like `if (b) List(1) else Vector(1)`. On t498, w3-base also hangs with -Ycheck:uncurry alone. On the base, any earlier check phase together with uncurry silences the uncurry check, while running the checker after the run reports again. The integration builds lose that accident through PR 459 (non-destructive -Ycheck). That is the only merged change that removes checker side effects, and no merged PR touches lub or existential code. This is not a finding against PR 459. Fix: on the -Ycheck stack (PR 459/509), treat type parameters bound inside the checked type as bound, as 459 does for existential quantifiers, and truncate the signature while printing it.
